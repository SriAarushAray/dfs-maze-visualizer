Depth-First Search (DFS) Properties
Theoretical Analysis & Guarantees
Q: Is DFS Complete?
Yes, in finite state spaces with graph search (using the explored set to prevent cycles). No in infinite spaces without loop checking.
Q: Is DFS Optimal?
No! DFS returns the first path it stumbles upon. As shown on this maze, it often finds a winding path rather than the shortest path.
Q: Time Complexity?
O(b^m) where b is the maximum branching factor and m is the maximum depth of the state space.
Q: Space Complexity?
O(b × m) — extremely memory efficient! It only stores the active path plus sibling alternatives in the stack.
Key Takeaways & Search Comparisons
  • 1
    Deep Exploration Before Backtracking: DFS plunges down a single trajectory until it reaches a dead end or the goal. It only backs up when all legal actions from the current frontier branch have been exhausted.
  • 2
    Low Memory Consumption: Unlike BFS which stores entire frontier widths, DFS only maintains the current active path plus untried sibling branches, requiring O(b × m) space.
  • 3
    Finds a Solution, But Not Necessarily Shortest: DFS is not optimal in unweighted graphs. Because it commits deeply to the first path it stumbles into, it may discover a long winding route instead of the minimal step trajectory.
